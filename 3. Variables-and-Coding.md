# Variables and Coding

## Scope

This document defines how variables in MoBa are represented, coded, and interpreted. It specifies the constraints necessary to ensure consistent use of variables across datasets, time points, and questionnaire versions.

The content assumes familiarity with the overall data structure and identifier system described in the overview.

---

## Variable Definition

MoBa variables originate primarily from questionnaire data and are supplemented by derived variables and registry-based measures.

Each variable represents either:

- a direct response to a questionnaire item  
- a derived construct based on one or more variables  
- a registry-based measure linked to the cohort  

The meaning of a variable is determined by the combination of its label, coding scheme, and context of data collection.

---

## Variable Naming

Variables are named using a structured system typically consisting of:

- a prefix indicating the questionnaire  
- a numeric identifier corresponding to the item  

Examples include:

- `AA123` → questionnaire 1 variable  
- `CC456` → questionnaire 3 variable  

Variable naming is not uniform across all datasets and should not be used as the sole basis for interpretation.

---

## Coding Structure

Most variables follow simple categorical or ordinal coding schemes:

- Categorical variables are coded as integer values  
- Response categories are typically ordered  

However, no global coding convention is enforced across all variables.

In particular:

- The direction of coding (e.g., low → high) is not consistent  
- Binary variables may be coded with either ordering  

All coding must therefore be interpreted at the variable level.

---

## Missingness

Missing values arise from:

- non-response  
- inapplicability of questions  
- data processing decisions  

Missing values are typically represented as:

- empty fields  
- system missing values  

The absence of a value does not imply a specific category and must be handled explicitly.

---

## Questionnaire Versions

Many variables are affected by the existence of multiple questionnaire versions.

Consequences include:

- variation in question wording  
- variation in response categories  
- version-specific variables  

Variables with identical names across versions are not guaranteed to be equivalent.

All analyses involving pooled data must verify comparability across versions.

---

## Derived Variables

Derived variables are constructed through transformation or combination of primary variables.

These may involve:

- aggregation across time points  
- recoding of categorical variables  
- integration of multiple data sources  

Derived variables are not standardised across projects and must be fully documented.

---

## Analytical Constraints

Use of variables in analysis requires:

- verification of coding schemes  
- validation of variable definitions  
- alignment of variables across time points  
- consistency in handling missing values  

Assumptions of equivalence or consistency without verification should be avoided.

---

## Summary

Variable interpretation in MoBa depends on:

- correct identification of the underlying questionnaire item  
- explicit understanding of coding schemes  
- verification across questionnaire versions  

These steps are necessary to ensure valid and reproducible analyses.
