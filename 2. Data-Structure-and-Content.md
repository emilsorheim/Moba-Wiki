# Data Structure and Content

## Overview

MoBa data is distributed across multiple datasets representing:

- Questionnaire data collected at different time points  
- Participants (mothers, fathers, and children)  
- Registry-based data  
- Derived and project-specific datasets  

MoBa is a **longitudinal, relational dataset**, meaning that:
- Participants are followed over time  
- Data is spread across multiple files  
- Datasets must often be merged for analysis  

A correct understanding of structure and identifiers is essential before working with the data.

---

## Core Entities

MoBa is built around three main participant groups:

| Entity   | Description |
|----------|------------|
| Mother   | Woman enrolled during pregnancy |
| Father   | Partner of the mother |
| Child    | Offspring followed from birth onward |

These entities are typically linked through shared identifiers.

---

## Units of Observation

The unit of observation varies across datasets:

- **Pregnancy-level data**  
  - Used for questionnaires during pregnancy  
  - One row per pregnancy  

- **Child-level data**  
  - Used for post-birth questionnaires and registry data  
  - One row per child  

⚠️ This distinction is critical when merging datasets.

---

## Key Identifiers

The most important identifiers used in MoBa include:

| Variable | Description |
|----------|------------|
| `PREG_ID` | Unique identifier for each pregnancy |
| `BARN_NR` | Child number within a pregnancy (important for twins/triplets) |

### How identifiers are used

- Before birth:
  - `PREG_ID` uniquely identifies rows  

- After birth:
  - Combination of `PREG_ID` + `BARN_NR` is required  

⚠️ Always use both identifiers when working with child-level data to avoid incorrect merges.

---

## Data Organization

### Questionnaire Data

- Delivered as separate files per questionnaire (e.g., Q1, Q2, Q3)
- Each dataset typically contains:
  - One row per participant (or pregnancy/child)
  - One column per variable (question)

---

### Registry Data

- Linked to MoBa participants via identifiers
- Typically event-based (e.g., diagnoses, prescriptions)
- May contain multiple rows per individual

---

### Derived Data

- Variables created from one or more source datasets
- May include:
  - summary variables  
  - categorized variables  
  - computed outcomes  

---

## Longitudinal Structure

MoBa follows participants across time:

| Stage | Examples |
|-------|---------|
| Pregnancy | Week 17, 22, 30 questionnaires |
| Early childhood | 6 months, 18 months |
| Childhood | 3, 5, 8 years |
| Adolescence and beyond | Later follow-ups |

This results in:

- Repeated measurements  
- Multiple datasets per participant  
- Need for consistent time alignment  

---

## Relationships Between Files

MoBa datasets have different types of relationships:

- **One-to-one**  
  - Same participant across questionnaires  

- **One-to-many**  
  - Participant linked to multiple registry events  

- **Many-to-one**  
  - Multiple variables aggregated into derived measures  

---

## Merging Data

Merging datasets is a central task in MoBa analysis.

### General rules

- Use `PREG_ID` for pregnancy-level merges  
- Use `PREG_ID + BARN_NR` for post-birth data  

### Example

- Merge Q1 (pregnancy) with Q3:
  - Use `PREG_ID`  

- Merge questionnaire data with registry data:
  - Use both `PREG_ID` and `BARN_NR`  

---

## Questionnaire Versions

Many questionnaires exist in multiple versions:

- A, B, C, etc.  
- Some questions are identical across versions  
- Some differ significantly  

### Implications

- Variables may differ between versions  
- Not all participants have identical data  
- Harmonization may be required  

---

## Common Challenges

- Mixing pregnancy-level and child-level data incorrectly  
- Using incorrect identifiers in merges  
- Ignoring questionnaire versions  
- Misaligning time points  
- Not accounting for missing data  

---

## Best Practices

- Always identify:
  - unit of observation  
  - required identifiers  

- Before merging:
  - check dataset structure  
  - inspect variable availability  

- Document:
  - merge logic  
  - assumptions  
  - variables used  

---

## Summary

MoBa data is:

- **Longitudinal** (collected over time)  
- **Relational** (linked across datasets)  
- **Multi-source** (questionnaires, registries, biology)  

Correct use of identifiers and understanding of structure is essential to ensure valid analyses.
